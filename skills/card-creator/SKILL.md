# Card Creator

“Magikarp × ICOCA, simple, ICOCA at lower right” is enough. Use the available image-generation tool to create the complete card, including its logos. Never draw the artwork with code or paste logos onto a generated background. If image generation is unavailable, say so instead of substituting a script.

1. Read the short [card rules](references/card-rules.md). When a logo is named, find it in the [picture index](references/logo-reference-index.md) and pass only its relevant picture(s) to image generation. Prefer the user's attached reference. If unavailable, use model knowledge; search only when requested or identification is genuinely uncertain. Do not audit the library or read source histories to make a card.
2. Generate from the user's subject, style and placement. Logos may become gold foil, monochrome or line art to suit the picture. Choose familiar card-face variants (usually compact UnionPay), not compact versions of every brand. Let the model balance logo size, spacing and illustration; there are no fixed logo boxes or size caps.
3. Return the generated image. Check that the requested subject and logos are recognizable and the layout feels balanced; correct a clear mistake without turning the task into a production pipeline.

For a wallet screenshot, use only the card's design as reference, not the surrounding interface. Do not add unrequested text, numbers, chips, QR codes or contactless/NFC symbols. Treat third-party marks as non-official artistic interpretations, not evidence of brand authorization or a functioning card. Do not publish private reference images without permission.
